Нужно написать новый класс, который будет заниматься отрисовкой графика коррекции АЧХ на основе загруженного IR (Impulse Response) файла. Требования к этому классу такие:
1) Класс должен уметь выполнять свою функцию при любом размере виджета. График должен соответствующим образом масштабироваться, чтобы занимать всю доступную площадь.
2) Класс должен отображать два графика одновременно: синий график (корректирующая кривая IR) и белый график (вычисленная оригинальная АЧХ наушников, являющаяся инверсией коррекции).
3) Входными данными для построения графиков являются два массива сэмплов IR файла (левый и правый канал) и частота дискретизации (sample rate). Класс принимает их через метод setIRData. Помимо этого класс принимает значение Dry/Wet Mix (от 0.0 до 1.0) через метод setDryWet.
4) Для вычисления АЧХ используется FFT. IR файл загружается, дополняется нулями до ближайшей степени двойки (максимум 131072 сэмплов), затем выполняется прямое FFT через vDSP_ctoz + vDSP_fft_zrip. Из результата FFT вычисляется спектр магнитуд для 100 равномерно распределённых по логарифмической шкале частот в диапазоне 20–20000 Гц (с линейной интерполяцией между соседними bins). Магнитуды обоих каналов усредняются. Все магнитуды нормализуются по пику (пик = 1.0, то есть 0 dB).
5) Синий график (коррекция) строится на основе усреднённой магнитуды IR в линейном домене. Белый график (оригинальная АЧХ) строится как обратная величина магнитуды коррекции (1/avgMag), масштабированная константой 10^(-24/20) ≈ 0.0631, так чтобы минимум белого графика при натуральном значении Dry/Wet попадал ровно на -24 dB (нижний край виджета).
6) Оба графика интерполируются по значению Dry/Wet в линейном домене звукового давления (magnitude), а не в Дб. Для синего графика смешивается плоский уровень (magnitude = 10^(-12/20) ≈ 0.2512, что соответствует -12 dB) с натуральной магнитудой коррекции: mixed = (1-t)*0.2512 + t*avgMag. Для белого графика смешивается натуральная инвертированная магнитуда с тем же плоским уровнем: mixed = (1-t)*(0.0631/avgMag) + t*0.2512. Результат конвертируется в Дб и зажимается в диапазон [-24, 0] dB.
7) При значении Dry/Wet = 0% (0.0): синий график — плоская линия на уровне -12 dB; белый график — натуральный вид, минимум на -24 dB. При значении Dry/Wet = 100% (1.0): синий график — натуральный вид, пик на 0 dB; белый график — плоская линия на уровне -12 dB. В промежуточных значениях оба графика интерполируются через линейное смешивание в звуковом давлении.
8) Горизонтальная шкала графика должна быть в логарифмическом виде. Левая граница = 20 Гц. Правая граница = 20000 Гц.
9) Вертикальная шкала графика должна быть в Дб. Нижний край графика -24 dB. Верхний край графика 0 dB.
10) Фон графика должен быть чёрного непрозрачного цвета.
11) Вдоль горизонтальной шкалы должны быть отметки заданных значений. Отметкой является тонкая вертикальная линия проходящая от самого низа графика до самого верха. Отметки имеют разные цвета линий. Белой линией отмечаются эти значения: 100 Гц, 1000 Гц, 10000 Гц. Серой линией отмечаются эти значения: 20 Гц, 30 Гц, 40 Гц, 50 Гц, 200 Гц, 300 Гц, 400 Гц, 500 Гц, 2000 Гц, 3000 Гц, 4000 Гц, 5000 Гц.
12) Вдоль вертикальной шкалы нужны отметки на значениях: -18 dB, -12 dB, -6 dB, 0 dB. Эти отметки делаются тонкой серой линией проходящей от левого края графика до правого края графика.
13) Синий график должен быть отрисован синим цветом линией толщиной 3 пикселя. Пространство от синего графика до низа виджета должно быть залито синим полупрозрачным цветом (rgba 0, 0, 255, 100). В качестве дополнительных точек для контура заливки нужно использовать левый нижний угол и правый нижний угол графика.
14) Белый график должен быть отрисован белым цветом линией толщиной 3 пикселя, поверх синего графика и его заливки. Белый график не имеет заливки.
15) Оба графика строятся сплайнами (Catmull-Rom, 4 подотрезка на каждый сегмент) по 100 контрольным точкам.
16) Класс должен сохранять переданные ему значения магнитуд (m_magL, m_magR, m_freqHz) для того, чтобы уметь пересчитывать и отрисовывать графики при изменении Dry/Wet или при перерисовке, запрошенной ОС или фреймворком. При вызове clear() все данные сбрасываются и график отрисовывается пустым (только оси и отметки).
